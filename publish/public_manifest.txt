# =============================================================================
# What goes into the PUBLIC pipeline repository (malavi-db/malavi-pipeline).
# Read by publish/push_pipeline.sh. Nothing not listed here is ever copied.
# =============================================================================
#
# WHY AN ALLOWLIST AND NOT A LIST OF EXCLUSIONS
# ---------------------------------------------
# The private repository holds submissions from people who have not published yet,
# curator identities, working notes and credentials. A list of things to leave behind
# fails the first time somebody adds a file nobody thought of: the new file is public by
# default, and nobody finds out. A list of things to take fails the other way -- a new
# file is absent until somebody adds it here on purpose. Absent is recoverable. Published
# is not.
#
# This is the same reasoning that makes publish/push_site.sh copy docs/ and only docs/.
#
# FORMAT
# ------
#   path            a file, copied to the same path in the public repo
#   path/           a directory, copied recursively
#   src -> dest     copied under a different name
#   # comment       ignored
#
# Directory copies still skip the junk listed in ALWAYS_SKIP in push_pipeline.sh
# (__pycache__, .pyc, .DS_Store and so on), because those are noise in every tree.
#
# WHAT DELIBERATELY IS NOT HERE, AND WHY
# --------------------------------------
#   config/project.yml     holds live Drive folder ids, sheet ids, form edit URLs and the
#                          report endpoint. A sanitized project.example.yml is GENERATED
#                          from it by the publisher, with every such value blanked.
#   config/curators.yml    real curator addresses and personal aliases. An example ships
#                          instead.
#   curation/intake/       submissions, including unpublished sequences from people who
#                          asked us to hold them. The single most important exclusion.
#   curation/benchmark/    papers and ground-truth annotations built from them.
#   data/                  the record store, which accumulates submissions BEFORE they are
#                          released, including embargoed ones. The public artifact for
#                          data is the release, which is published separately.
#   docs/                  the rendered website. It has its own public repository already.
#   ops/*.html             build output; the same documents are already live on the site.
#   DELIVERY_PLAN.md       design argument, open problems, things not yet built.
#   CUSTODY_PRIVATE.md     recovery paths. Never, under any circumstances.
#   results/, legacy/,     working notes, scratch, archived material.
#   preview/               a development tool whose output inlines the whole submission
#                          queue into one file. Its own header says never to publish it.
